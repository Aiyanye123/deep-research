## 为什么做这个插件

Deep Research 是用于探索性研究与实质写作的本地 Codex 插件。当前版本为 **0.6.2**，支持用户文件、粘贴材料、已有稿件、网络来源及其组合。开头提问帮助拓宽或深化思路，研究、解释和写作可以自然往返。重要事实与结论按影响核查，每篇文章都实际进行结构审阅和最后的语言润色。

它主要面向：

- 文学、影视与文化批评
- 学术论文、政策研究和研究报告
- 市场、行业、金融和法律分析
- 需要数千字到数万字的证据型长文
- 需要图表、示意图或解释性图片的研究成果

## 核心能力

- **探索性提问**：新任务第一次实质回复提问并等待回答，只有用户明确要求时才跳过；完整需求与引用旧会话不算已完成问答。
- **按需或完整执行**：不指定流程时按需选用技能，明确要求默认全流程时使用全部七个技能。
- **多种材料输入**：通过宿主工具读取实际文件与材料，可以只用文件写作，不强制联网。
- **原创理解**：允许发展新联系、假设、不同解释与结构，不强迫创新，也不把资料摘要当成最终分析。
- **固定写作动作**：确定重心与组织、充分展开材料、审阅完整结构、润色语言并复查改动影响。
- **明确代理分工**：子代理承担有用的独立研究、事实核查、图表制作与完整稿件结构审阅；主代理保留核心理解、正文和最后的语言润色。
- **有用的可视化**：图表、示意图与明确标注的插图应帮助理解，纯文字适合时不强制做图。

## 工作流

```text
阅读输入并提问 -> 等待实际回答，确认方向
  -> 研究文件、网络资料或两者组合
  -> 核查重要发现
  -> 发展解释与组织结构
  -> 判断可视化需要，有用时制作
  -> 主代理撰写正文
  -> 子代理结构审阅，主代理落实有用的修改
  -> 主代理通读并润色全文语言
  -> 重点终稿核查，主代理修正并再润色受影响段落
```

明确要求“使用默认流程”“默认全流程”或“完整流程”时执行上述完整顺序；不指定时，模型按需选择技能。两种方式都保留开头提问与四个写作动作。发现可以改变暂定重心、解释和结构，不要求固定段落模板、问题数量、检索波次、来源配额、账本、双份草稿或完成证明。

## 安装

要求已安装支持插件市场的 Codex CLI。

```powershell
codex plugin marketplace add Aiyanye123/deep-research
codex plugin add deep-research@aiyanye-deep-research
```

安装或升级后请新建一个 Codex 任务，使新版 Skill 被完整加载。

## 使用

在 Codex 中选择 **Deep Research**，或直接提出类似请求：

```text
使用 Deep Research 默认全流程，根据这些文件写一篇文章。
开头问题请拓宽或深化我的思路，等待我回答后再正式研究。
```

希望按需使用时，选择插件而不指定完整流程，或明确要求按需选用技能。提问前可以阅读相关输入、做有限的定位检查；正式研究与起稿须等待实际回答，除非用户明确要求跳过提问。

子代理调度通过技能提示词和宿主工具执行，没有新增调度脚本。默认全流程中的结构审阅由子代理直接读取完整当前稿件、用户目的与约束及相关原材料，返回问题位置与修改建议；主代理裁决、落实修改并亲自完成最后的语言润色。独立研究、核查和制作任务在确有工作且交接省力时委派，不按技能数量创建代理。子代理不可用或用户禁止时，主代理完成必要工作并如实说明。

## 七个 Skill

| Skill | 职责 |
| --- | --- |
| `deep-research` | 开头问答、流程选择、固定写作动作与代理分工 |
| `research-orchestrator` | 来源发现、研究策略、缺口与停止条件 |
| `evidence-auditor` | 重点事实、引用和来源支持核查 |
| `insight-architect` | 原创联系、解释、组织和结构审阅 |
| `research-visualizer` | 图表、表格、示意图和生成图片 |
| `longform-writer` | 主代理正文写作与连续性 |
| `prose-humanizer` | 必做的成稿审阅与主代理语言润色 |

使用某个技能时读取其说明并实际执行。主代理亲自阅读决定核心理解的原始材料，不只依赖子代理摘要；已充分核查的普通结果无需重复检查。使用统筹模式时也保留相同写作职责边界。

## 中文写作配置

写作方向根据用户目的、偏好、读者和材料选择，题材和发布平台不自动决定文体与声音。中文写作参考提供以下可按需使用的倾向：

- `essayistic`：强调解释、判断和行文节奏，允许有依据的第一人称与不完全对称的段落结构。
- `formal`：强调精确归因、论证边界、稳定结构和规范的研究文档组成部分。
- `technical`：强调术语一致、条件明确、步骤直接，并精确保留代码、公式、单位和标识符。

优先自然、具体、准确的中文，使用准确动词、有效细节和有依据的判断。让论述连续展开，避免反复转折、防御性套话与段末警句；理论须帮助解释材料，有作用的歧义和修辞可以保留。学习样本的立场与推进方式，不把案例内容写进通用规则。保护事实、引文、术语及必要限定的含义，允许改写重复提醒。不强制创建风格表或双份稿件。

需要诊断具体中文表达问题时，可选择运行：

```powershell
python plugins/deep-research/scripts/check_chinese_prose.py <稿件.md> --profile <essayistic|formal|technical>
```

检查器只将模型自述、对话结尾和不透明的宣传黑话等高置信残留判为失败。标点、转折、第一人称和依赖语境的术语最多产生警告，不会被机械删除。直接引语、引文标记、参考文献、表格、图注、链接、代码、名称、数字和机器字段受到保护。英文及其他语言使用对应语言的润色规则，不运行中文检查器。

## 研究深度

研究深度由问题、重要未知与有价值的线索决定。阅读关键来源，比较相关解释，补充可能改变答案的缺口；中心解释已有支持且继续研究不太可能带来实质改善时停止。不凑来源数量，也不假称穷尽全部资料。旧的深度配置和门控仅属于用户明确选择的会话管理流程。

## 会话与评估

有用的来源位置、重要发现与未解决问题可以保存在会话上下文或简短笔记中；长项目、续接和交接需要时再使用文件。现有 `research_session.py` 与 `evaluate_run.py` 只用于用户明确选择的管理流程，或已经使用它的旧项目；长任务或严肃任务不会自动启用。结构检查不能证明研究质量，须遵守用户的验证限制。

对明确选择的管理会话，可使用其结构评估器：

```powershell
python plugins/deep-research/scripts/evaluate_run.py --session <研究会话目录>
```

## 验证

修改插件时检查技能元数据、插件清单及受影响工具。`tests/` 保留了可选会话管理工具的测试。按改动范围与用户工具限制选择检查，结构校验不能证明实际模型行为、原创性或成文质量；这些需要真实研究与写作测试。
